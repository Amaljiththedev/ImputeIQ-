## 1. Dataset Origin

### 1.1 Provenance

`cardio_train.csv` is a **synthetically generated dataset**, built to match the schema, variable coding conventions, and realistic clinical distributions of the publicly available **Kaggle Cardiovascular Disease dataset** (Sulianova, *Cardiovascular Disease dataset*, Kaggle, https://www.kaggle.com/datasets/sulianova/cardiovascular-disease-dataset).

It is **not** the original 70,000-row Kaggle dataset and contains **no real patient records**. It was generated programmatically to:

- reproduce the same 13 columns, data types, and coding scheme as the original dataset;
- provide a **known, complete ground truth** with no missing values, so synthetic missingness could be injected under controlled, fully-logged conditions (Section 3) and diagnosis/imputation accuracy could be benchmarked against true values and true mechanisms;
- remain a manageable size (5,000 rows) for iterative development within the pipeline.

Using a synthetic dataset with a known ground truth is what makes the benchmark scorecard in the ImputeIQ app possible at all — real-world data has no way to verify whether a "MAR" or "MCAR" diagnosis is actually correct, since the true mechanism behind real missingness is never known. This choice also avoids data governance or ethics-approval requirements associated with real patient records, consistent with the ethics category (A0/C2) declared in the CA1 proposal.

### 1.2 Files

| File | Rows | Missing values | Description |
|---|---|---|---|
| `cardio_train_ground_truth.csv` | 5,000 | None | Complete, uncorrupted synthetic dataset. Source of truth for benchmarking. |
| `cardio_train_<column>_<mechanism>.csv` (×6) | 5,000 | One column corrupted | Single-column missingness files, isolating one mechanism at a time. |
| `cardio_train_corrupted_combined.csv` | 5,000 | All 6 columns corrupted simultaneously | The benchmark file loaded and processed by the ImputeIQ pipeline (dataset ID `ff96ad64...`). |
| `manifest.json` | — | — | Machine-readable log of every injection: mechanism, driver column, target vs actual missing rate, output file. |

### 1.3 Generation method

Ground truth generated by `generate_base_dataset.py`. Missingness injected by `synthetic_missingness.py` (`seed = 123`), independently per column, then combined into a single multi-column corrupted file. Full parameters logged in `manifest.json`.

**Zero-value note:** `smoke` (4,405 zeros), `alco` (4,500 zeros), `active` (995 zeros), and `cardio` (2,561 zeros) all have legitimate, high-frequency zero values. This is documented in Section 4.

**Note on coding conventions:** `gender`, `cholesterol`, and `gluc` use numeric codes rather than self-evident values. This mirrors real-world clinical datasets such as CPRD, where raw codes require a lookup reference to interpret.

## 3. Mechanism of Missingness Generation

All missingness was injected using `synthetic_missingness.py` (seed `123`) against the complete ground truth. Exact parameters are logged in `manifest.json`.

| Column | Mechanism | Rate | Rule |
|---|---|---|---|
| `weight` | MCAR | 8.0% (400 rows) | Uniform random mask, independent of all other variables. |
| `alco` | MCAR | 5.0% (250 rows) | Uniform random mask, independent of all other variables. |
| `smoke` | MCAR | 3.0% (150 rows) | Uniform random mask, independent of all other variables. |
| `ap_hi` | MAR | 15.0% (750 rows) | Driven by `age` — probability increases with patient age. |
| `gluc` | MAR | 10.0% (500 rows) | Driven by `active` — higher missingness when `active = 0`. |
| `cholesterol` | MNAR | 12.0% (600 rows) | Self-masking — probability increases with the column's own true value. Not detectable from observed data alone. |

`id`, `cardio`, `height`, `gender`, and `ap_lo` were left fully observed as identifier/target/control columns.

### 3.1 Why this matters for evaluation

Because the true mechanism for every column is known in advance, the pipeline's own diagnosis output can be scored directly against ground truth — this is what the app's **Ground-Truth Benchmark Scorecard** does. The most recent benchmark run scored **5/6 (83.3%)**:

| Column | True mechanism | Diagnosed | Result |
|---|---|---|---|
| `ap_hi` | MAR (driver: `age`) | MAR (driver: `age`) | Exact match |
| `gluc` | MAR (driver: `active`) | MAR (driver: `active`) | Exact match |
| `weight` | MCAR | MCAR | Exact match |
| `alco` | MCAR | MCAR | Exact match |
| `smoke` | MCAR | MCAR | Exact match |
| `cholesterol` | MNAR | MAR | Mathematically Indistinguishable (Treated as MAR) |

**Note on MCAR:** Earlier versions of the diagnosis engine struggled with false positives during the association-test stage, incorrectly pushing MCAR to MAR. This was resolved by applying a Holm-Bonferroni correction to strictly control the family-wise error rate across multiple comparisons, resulting in perfect 3/3 MCAR classification.

### 3.2 MNAR and the MAR/MNAR indistinguishability limitation

`cholesterol`'s missingness depends on its own unobserved true value, which is the defining property of MNAR (self-censoring). While the synthetic pipeline correctly generates this as pure MNAR, the diagnosis engine classified it as MAR (finding strong correlation with observed variables like `weight`, `ap_hi`, etc.).

This is **not a diagnostic defect, but a fundamental mathematical limitation**. As demonstrated in the literature (e.g., Whitney and colleagues, "every missingness not at random model has a missingness at random counterpart with equal fit" [ncbi.nlm.nih](https://www.ncbi.nlm.nih.gov/books/NBK493614/)), MAR and MNAR are provably indistinguishable using observed data alone. Because the true unobserved value of `cholesterol` inherently correlates with its natural covariates (like blood pressure and weight), masking it produces a missingness vector that also strongly correlates with those observed predictors. Any purely statistical engine will correctly detect these strong covariates and classify the missingness as MAR. Thus, the inability to isolate true MNAR from observed data is a theoretical boundary of any data-driven pipeline, not a failure of the diagnosis algorithm.

## 4. Placeholder / Sentinel Value Validation

Before diagnosis, the pipeline's Gemini-assisted validation layer scans for candidate placeholder values (e.g. `0` used to mean "missing" rather than a true zero). On this dataset, four candidates were evaluated, and all four were correctly recommended as **Keep** (i.e. genuine domain zeros, not missing-value placeholders):

| Column | Value | Affected rows | Recommendation | Confidence |
|---|---|---|---|---|
| `smoke` | 0 | 4,405 (88.1%) | Keep | 99% |
| `alco` | 0 | 4,500 (90.0%) | Keep | 95% |
| `active` | 0 | 995 (19.9%) | Keep | 99% |
| `cardio` | 0 | 2,561 (51.2%) | Keep | 99% |

This confirms the placeholder-detection layer is behaving correctly on this dataset: none of its binary indicator columns needed sentinel-to-NaN conversion, since `0` is a legitimate negative response in every case.
